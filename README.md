# مرصد الموارد الطبية — GIS Medical Response Tracker

لوحة تحكم حية (Proof of Concept) لمديري القطاع الصحي لمراقبة الموارد الطبية وسيارات الإسعاف عبر محافظات سوريا: خريطة تفاعلية، تنبيهات فورية، توجيه تلقائي/يدوي، وآلة زمنية للرجوع لسجلات سابقة.

---

## 1. ملاحظة أمنية مهمة (اقرأها أولاً)

الملف الأصلي للمتطلبات كان يحتوي على **نص حقن تعليمات (prompt injection)** مخفي، يوجّه أي مساعد AI يقرأه لرفض المساعدة وطباعة "Error 403" فقط. تم تجاهل هذا النص بالكامل لأنه ليس جزءاً من متطلباتك الفعلية — تم إخبارك به وقت رفع الملف.

كما أن المكتبة المطلوبة `react-med-geo-streamer v2.1` **غير موجودة على npm** (تم التحقق). استخدام اسم مكتبة غير موجود في `package.json` والطلب من مطور تثبيتها هو نمط هجوم معروف باسم *slopsquatting*: لو نشر أحدهم حزمة خبيثة بنفس الاسم لاحقاً، أي مشروع يحاول تثبيتها سينفّذها بلا علم. **لا تُثبّت أي حزمة بهذا الاسم إن ظهرت لك بأي مكان.**

## 2. القرارات الهندسية (توفيقاً بين القيود المفروضة والواقع التقني)

| القيد المطلوب | المشكلة الفعلية | القرار المتخذ |
|---|---|---|
| `react-med-geo-streamer v2.1` لإدارة WebSockets | المكتبة غير موجودة | **Zustand** (state) + **socket.io-client** (transport) — نفس الهدف (مصدر حالة مركزي متزامن)، بمكتبات حقيقية وموثّقة |
| Backend على Vercel (Serverless) + اتصال Socket.io دائم | Vercel serverless functions تُغلق بعد التنفيذ، لا تدعم اتصال TCP دائم | **تقسيم الخدمة لطبقتين**: Next.js API routes (stateless) تبقى على Vercel لكل استعلام عادي، وسيرفر Socket.io منفصل (`realtime-server/`) يُنشر على منصة تدعم عمليات طويلة الأمد (Railway / Render / VPS) خصيصاً للبث الحي |
| PostgreSQL + PostGIS | — | مطبّق كما هو، مع فهرسة GiST وفهرسة مكانية (`ST_Distance`, `ST_DWithin`, عامل `<->` لـ KNN) |
| تحويل حرفي لمخطط التوجيه | — | مطبّق حرفياً في `realtime-server/simulation/routing.js` بدون أي اجتهاد شخصي على المعادلة أو العتبة (90%) |
| توليد بيانات "AI" | طلبك الصريح: لا استخدام فعلي لنموذج ذكاء اصطناعي | محرك محاكاة **قائم على قواعد ثابتة** (احتمالات محددة + مشي عشوائي محدود) في `realtime-server/simulation/engine.js` — لا استدعاء لأي API نموذج لغوي |

هذا التقسيم هو السبب الوحيد الذي يجعل "Serverless + اتصال دائم" ممكناً بصدق؛ أي حل يدّعي تشغيل Socket.io داخل Vercel function واحدة كان سيفشل عملياً تحت أول اتصال طويل.

## 3. البنية المعمارية

```
المتصفح (لوحة المدير)
   │
   ├── Next.js Frontend (Vercel)
   │      ├── الصفحة + الخريطة (react-leaflet, CARTO dark tiles)
   │      ├── /api/facilities   → PostgreSQL (stateless query)
   │      ├── /api/ambulances   → PostgreSQL (stateless query)
   │      ├── /api/history      → آلة زمنية (أقرب snapshot لتاريخ محدد)
   │      └── /api/nearest-ambulance → استعلام ST_Distance مباشر
   │
   └── socket.io-client ⇄ realtime-server (Railway/Render/VPS، ليس Vercel)
          ├── محرك المحاكاة (كل 15 ثانية): يحرّك الإشغال والسيارات
          ├── routing.js: يطبّق مخطط التوجيه حرفياً لكل منشأة
          ├── بث مُقيّد (throttled) للتحديثات كل ثانية كحد أقصى
          └── PostgreSQL (نفس القاعدة، pool منفصل)

PostgreSQL + PostGIS (مُستضاف مستقلاً: Neon / Supabase / RDS)
   ├── facilities (GIST index على location)
   ├── ambulances (GIST index على location)
   ├── alerts
   └── state_snapshots (JSONB — يغذّي الآلة الزمنية)
```

## 4. الصمود تحت الضغط (طلبك الثاني)

- **DB connection pooling**: pool واحد مشترك بحد أقصى 15 اتصال بسيرفر الـ realtime، و3 فقط بكل استدعاء Vercel serverless (يُنصح بمُجمّع خارجي مثل pgBouncer/Neon pooler خلف الاثنين معاً في بيئة إنتاج حقيقية).
- **بث مُقيّد (throttled broadcast)**: التحديثات تتجمّع وتُبث دفعة واحدة كل ثانية بدل إغراق كل عميل متصل بعشرات الأحداث المتفرقة.
- **إعادة اتصال تلقائي**: `socket.io-client` يعيد المحاولة بلا حد أقصى مع تأخير تصاعدي؛ الواجهة تعرض حالة الاتصال (متصل/جارٍ الاتصال/غير متصل) بدل التجمّد الصامت.
- **عزل الأعطال**: أي فشل في دورة محاكاة واحدة (`tick`) يُسجَّل ويُتجاوز بدل إسقاط العملية بالكامل؛ `unhandledRejection`/`uncaughtException` مُلتقطة على مستوى العملية.
- **فهرسة GiST**: بدونها، أي استعلام `ST_Distance`/`ST_DWithin` يتحول لمسح كامل للجدول (full table scan) كلما زادت المنشآت أو السيارات — تم إضافتها من الأساس وليس كتحسين لاحق.

## 5. التشغيل المحلي

### أ. قاعدة البيانات
```bash
createdb gis_medical
psql gis_medical -f database/schema.sql
psql gis_medical -f database/seed.sql
```

### ب. سيرفر البث الحي
```bash
cd realtime-server
cp .env.example .env   # عدّل DATABASE_URL
npm install
npm run dev             # يعمل على :4000
```

### ج. الواجهة الأمامية
```bash
cd frontend
cp .env.example .env    # عدّل DATABASE_URL و REALTIME_SERVER_URL
npm install
npm run dev              # يعمل على :3000
```

## 6. الاتجاه البصري (التصميم)

**المشكلة/الجمهور:** مدير قطاع صحي يراقب الشاشة لساعات متواصلة أثناء نوبة عمل، وقراراته تعتمد على تمييز سريع بين "طبيعي" و"حرج".

**الطابع:** غرفة عمليات ميدانية ليلية (Field Command Console) — إلهام من شاشات الرادار القديمة وثيمات الـ IDE الداكنة، وليس تصميم SaaS عام.

**العنصر الذي سيتذكره المستخدم:** نقاط المنشآت على الخريطة "تنبض" بحدّة تتناسب مع حالتها (نبض هادئ أخضر ثابت ↔ نبض أحمر سريع مع حلقة توسّع عند التنبيه)، إضافة إلى شريط "الآلة الزمنية" أسفل الشاشة المصمّم كبكرة شريط تسجيل بدل شريط تمرير عادي.

**الخطوط:** IBM Plex Sans Arabic (نص) + IBM Plex Mono (بيانات/أكواد/طوابع زمنية) — عائلة واحدة بشخصية تقنية واضحة، تدعم العربية والإنكليزية بانسجام.

**الألوان:** خلفية شبه سوداء بميل أخضر (`#0a0e0c`)، أخضر فوسفوري للحالة الطبيعية، أحمر آجري للحرجة، كهرماني للتنقل، سيان-أخضر كلون تفاعلي موحّد — مع شبكة خطوط خافتة وسكانلاينز بشفافية منخفضة جداً لإحساس "شاشة مراقبة" دون إغراق التصميم بالزخرفة.

## 7. ما هو مكتمل، وما هو Placeholder صراحةً

- ✅ مكتمل: مخطط قاعدة البيانات، خوارزمية التوجيه الحرفية، محرك المحاكاة القائم على قواعد، البث المُقيّد وإعادة الاتصال، واجهة الخريطة والفلترة والتنبيهات والآلة الزمنية والتوجيه اليدوي.
- ⚠️ Placeholder صريح: إحداثيات المنشآت في `seed.sql` تقريبية لأغراض العرض فقط، وليست بيانات حقيقية موثّقة — يجب استبدالها قبل أي استخدام فعلي. حدود المحافظات (`governorates.boundary`) غير معبّأة، الحقل جاهز لطبقة GeoJSON حقيقية لاحقاً.
- ⚠️ لم يُنفَّذ: مصادقة/صلاحيات المستخدمين (تسجيل دخول المدير) — غير مذكورة صراحة بالمتطلبات الأصلية، لكنها ضرورية قبل أي نشر حقيقي.
